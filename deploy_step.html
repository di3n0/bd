逐步部署到 Kubernetes

建立 Namespace、Secret、RBAC、四組 wrapper Deployment 與 ClusterIP Service，再用 dry-run 驗證 client 設定。

① 選 Mode / 說明
② 預設 / 調整
③ Dry-run
④ Submit + Poll
正式 Token 不可提交 Git。請使用 Kubernetes Secret、External Secrets 或組織核准的 Secret Manager。
1

確認 Kubernetes 權限

確認目前 context、目標 cluster 與建立 Namespace、RBAC、Deployment、Service、Secret 的權限。

kubectl config current-context
kubectl auth can-i create deployments.apps
kubectl auth can-i create services
kubectl auth can-i create roles.rbac.authorization.k8s.io
2

設定 Wrapper Image

編輯 k8s/workloads.yaml，將四個 your-registry/*-wrapper:latest 改成實際映像檔。

grep -n "image:" k8s/workloads.yaml
kubectl apply -f k8s/namespace.yaml
3

建立正式 `.env`

複製範例後，填入 Black Duck 與 K8s 內部服務網址。不要提交 `.env`。

cp assets/.env.example .env
chmod 600 .env
nano .env
服務網址
DETECT_SERVICE_URL
SIGNATURE_SERVICE_URL
BDBA_SERVICE_URL
IMAGE_SERVICE_URL
狀態輪詢
STATUS_POLL_INTERVAL_SECONDS=15
STATUS_MAX_WAIT_SECONDS=0
STATUS_POLL_ENABLED=true
Pod CPU
*_POD_CPU_REQUEST
*_POD_CPU_LIMIT
Pod Memory
*_POD_MEMORY_REQUEST
*_POD_MEMORY_LIMIT
Black Duck Proxy
HTTP_PROXY=http://xxx.xx.xx:xx
HTTPS_PROXY=http://xxx.xx.xx:xx
NO_PROXY=localhost,.svc
Proxy Credentials
HTTPS_PROXY=http://user:password@host:port
帳密只經由協定專屬 HTTP header 傳送

5

先做 Dry-run

確認 endpoint、timeout、Pod resources 與 polling 設定，這一步不送 HTTP。

python3 scripts/blackduck_scan.py \
  --env-file .env \
  --mode image-deep \
  --target registry.example.com/team/app:1.0 \
  --project demo-app \
  --version 1.0 \
  --dry-run
6

送出並追蹤狀態

移除 --dry-run 後，client 會依 `.env` 頻率 GET statusUrl，直到成功、失敗或超時。

python3 scripts/blackduck_scan.py \
  --env-file .env \
  --mode image \
  --target registry.example.com/team/app:1.0 \
  --project demo-app \
  --version 1.0

單次覆寫範例：--cpu-request 1 --cpu-limit 4 --memory-request 2Gi --memory-limit 8Gi --poll-interval 10

7

Kubernetes Wrapper 必要行為

正式服務需接受 POST /scan，將 podResources 套到新建 Job 的 container resources，並回傳可查詢的 statusUrl。

{
  "status": "QUEUED",
  "requestId": "...",
  "statusUrl": "http://service/status/..."
}

詳細 JSON 契約：references/service-contract.md。正式環境同時要在服務端限制併發與 timeout，client 限制不是 admission control。
